## M1：Android 上的第一个完整学习项目

目标：用户导入一份材料，围绕一个学习目标进行讲解/研究，并保存能返回原文的成果。

已开始：本地语料索引能读取科目目录中的教材和讲解 PDF，以及对应的解析稿，
原文不进入仓库。Android 发布先用手动工作流 `android-arm64.yml`，只打 arm64-v8a。

已接入应用（2026-10-18，详见[质量审查第三轮](QUALITY_REVIEW.md)）：学习项目的创建与模式选择、
材料复制导入与状态、MinerU 解析稿挂接、章节索引、项目讨论（绑定会话获得材料与引用协议）、
回复中的可核查引用角标、原文阅读与跳转、带依据状态的笔记。对应范围 1–5 的首个版本；
真机验收和快模型索引入口仍待完成。

品牌切换（2026-10-18，第 6–7 项）：应用名 StudyPi，Android 包标识 `app.studypi`，可与 Kelivo
同时安装；正式图标为“π 延伸出足迹通向星星”（深青底、暖金星），源文件在 `assets/brand/`，
由 `tool/render_brand_icons.sh` 渲染，含 Android 自适应与主题单色图标；启动页使用同一底色。
更新入口改为读取本仓库 GitHub Releases，没有 Release 时不提示。`android-arm64.yml` 产出只含
arm64-v8a 的签名 APK。仍保留 Kelivo 名称的部分：Kotlin 包与 namespace、Dart 包名（便于合并上游）、
iOS bundle ID 与 App Group（需要 Apple 账号侧同步切换）、桌面端可执行文件名（决定桌面数据目录），
以及应用内 `kelivo-file://` 等数据协议标识。版本号仍沿用 1.3.1+80。

范围：

1. 学习项目模型、Drift 仓库、项目与现有会话关联。
2. 文本与文本型 PDF 材料导入，保留原件、解析版本和页码锚点；扫描件在 OCR 不可用时明确提示。
3. 项目首页、材料阅读、讨论和成果视图；复用现有模型配置与工具。
4. 用户可明确选择直接讲解或引导练习；系统提示编辑处展示固定核心与自定义部分的关系。
5. 片段引用、原文跳转、可保存笔记；无可验证来源时显示依据不足。
6. StudyPi app 名、Android 包标识、图标、启动页与更新入口一起切换。
7. 配置 Android 构建链并产出可安装的开发 APK。

验收：

- 新安装无需产品账号即可创建项目，配置自己的模型并完成上述流程。
- 关闭重开后材料、会话、引用和成果仍可访问；无网络时保留本地阅读能力。
- 两个不同项目的材料不串入上下文；同名但不同内容的文件能区分。
- 320–600dp 常见宽度、大字号、键盘与语音草稿不遮挡核心操作。
- APK 能与 Kelivo 同时安装；启动、分享导入、文件预览和后续更新路径正确。

## M2：可检查的路由与研究协作

目标：小模型在需要时协助分流，主 agent 根据场景和实际能力协调任务。

范围：能力目录、模型角色配置、路由 schema、预算、任务状态、材料阅读/检索/复核角色。
加入结构化的概念与表现证据，先支持一次口头或文字解释的学习反馈。
资料检索必须保留原文定位，加入支持/反对证据表。

验收：

- 手动选择能覆盖自动路由；配置不存在或缺少所需模态时不会发出无效调用。
- 路由超时、JSON 无效、小模型不可用时有明确且有界的恢复路径。
- 简单提问无需先启动一组 agent；复杂任务能并行阅读独立材料并聚合出处。
- 每次任务显示选择理由、实际用量及缺失项；预算到达时停止新调用。
- 复核发现错误会回到主任务，不用多个模型一致作为正确性证明。
- 至少两个不同协议的已配置模型跑完行为集，并保存输出与人工评价。

## M3：双环境与可恢复实验

目标：同一学习项目可选择手机 Linux 或自己的服务器执行工具，结果回到项目。

范围：任务级环境绑定、文件后端、Runner 协议、产物传输、环境模板、检查点与恢复。
先支持用户自己的单用户服务器，使用设备/项目范围内的可撤销凭证；共享多租户部署另行扩展。

验收：

- 同一 Python 小实验在手机与服务器执行，输入摘要、方法和输出可核对。
- 执行结果与文件浏览始终来自选定主机；两个主机同路径不会混淆。
- 服务器任务在手机断网后继续，重连恢复状态和事件，不重复运行有副作用的步骤。
- 上传中断可恢复；未完成传输不会被当作完整数据执行。
- 取消、超时、空间不足、依赖缺失、权限不足都有真实终态和已保存产物。
- 挂载、读写和文件下载无法越出授权项目；并发任务不互相覆盖。

## M4：学习连续性、语音与账号

目标：跨设备延续项目，语音输入与学习反馈可靠，复习建立在可查看的表现记录上。

范围：StudyPi 身份、设备管理、可选项目同步、统一 ASR 能力与转写片段、口述解释、复习队列。
保留已有备份与导出，并为新增实体补齐同一项目的备份完整性。

验收：

- 游客离线可用；账号加入前能选择关联项目，退出后凭证清理与本地资料策略明确。
- 两台设备离线编辑同一记录后有冲突处理；学习证据和删除状态不被静默覆盖。
- 用户可撤销设备，撤销后无法继续读取任务、文件或同步数据。
- 系统、离线和至少一种云端语音路径完成 Android 真机测试，包括权限、蓝牙、打断与弱网。
- 只用最终确认转写评价理解；识别错误可以单独更正与重新评价。
- 复习建议能追溯到具体表现，用户能调整、推迟和关闭提醒。

## 变更与验证纪律

每个里程碑单独形成可审查变更，包含触发场景、行为变化、测试和已知限制。
提交前执行仓库 `AGENTS.md` 的格式、静态分析和完整单元/组件测试。
原生能力另跑设备测试；模型行为另跑评估集，不互相替代。

默认不发布安装包、不部署公共服务或修改现有用户服务器；到对应阶段先准备具体可检查产物，
再依据届时用户授权执行发行或部署。

## 仍需在对应阶段确定

- M1：StudyPi 自己的版本号起点（目前沿用 Kelivo 的 1.3.1+80）；iOS 标识切换时间。
- M2：用户希望用于小模型、主 agent、复核及多模态的可用模型与预算。
- M3：服务器运行条件、资源上限与连接方式。
- M4：登录方式、服务端部署、同步范围、保留与删除要求。

这些选择不阻挡已确认的 M0 与 M1 基础开发；不用一次向用户收集全部信息。
